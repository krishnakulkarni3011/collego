DONE
----
1. ADMIN CAN NO LONGER UPLOAD RESUMES
   - Removed the Upload/Replace control (file picker) from the faculty table
     in Admin > Academics > <Department> > Faculty. The Resume column now
     only shows the status badge (None / Pending / Approved / Rejected) and a
     "View" link for resumes the faculty uploaded.
   - Removed the backend endpoints POST /api/admin/faculty/{id}/resume and
     DELETE /api/admin/faculty/{id}/resume, plus the matching service
     methods, so the capability cannot be used even by calling the API.
   - Admin can still review (Approve / Reject with a note) and download any
     faculty resume, including pending ones, from the same table.
   - Faculty continue to upload/replace/remove their own resume in
     Faculty Portal > Career Profile; self-uploads always start as PENDING.

2. ACCOUNT-CREATION EMAIL
   - Creating a student or faculty member now sends a plain-text email to the
     address entered by the admin.
   - The email contains: name, role, email, and the rest of the information
     entered by the admin (USN, department, semester, section, admission year
     for students; employee ID, designation, department for faculty), the
     temporary password, the sign-in link and a note that the password can be
     changed from Settings.
   - Sender/account: collego.admin@gmail.com (SMTP smtp.gmail.com:587, TLS,
     Gmail app password). Configurable through MAIL_ENABLED, MAIL_HOST,
     MAIL_PORT, MAIL_USERNAME, MAIL_PASSWORD, MAIL_FROM and FRONTEND_URL.
   - Mail failures are logged and never roll back account creation, so the
     admin is never blocked by an SMTP problem.
   - The admin success toast now reads:
     "User created - login details sent to <email>".
   - Production: MAIL_ENABLED=true and the Gmail app password are set in
     /opt/collego/.env (file mode 600) and passed to the backend container.
     A real test email was delivered to collego.admin@gmail.com and the
     backend logged "Email sent to collego.admin@gmail.com
     (Your Collego account is ready)". The temporary test account was then
     deleted from the database.
   - Local development: mail stays log-only (MAIL_ENABLED=false) and the full
     message is written to the backend log for inspection.

3. FACULTY TOP-RIGHT PROFILE
   - The faculty portal now loads the signed-in faculty member's career
     profile on mount and shows the real name plus department in the top bar
     (e.g. "Prof S.R Karjol" / "Professor - Computer Science & Engineering")
     instead of the placeholder "Faculty User" / "Faculty".
   - Verified on the live site: header text is
     "Prof S.R Karjol  Professor - Computer Science & Engineering".
