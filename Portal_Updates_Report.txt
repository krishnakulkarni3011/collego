COLLEGO - PORTAL UPDATES REPORT (updates.txt)
=============================================
Date: 24 October 2026
Scope: login page, admin portal, faculty portal, student portal, database
Status: implemented, verified locally, and deployed to production
        (https://65-0-244-196.sslip.io) on 24 October 2026.

------------------------------------------------------------
DONE
------------------------------------------------------------

1. LOGIN - GOOGLE SIGN-IN REMOVED
   - Removed the "Continue with Google" button from both login steps and
     deleted the placeholder handler. There is no backend OAuth code to
     remove (Google sign-in was frontend-only).

2. USN PATTERN - 2BA<YY>CS<NNN>
   - Format: 2BA = college code, YY = admission year, CS = department,
     NNN = student number 001-030 (restarts every academic year).
   - 23 = Final Year, 24 = III Year, 25 = II Year, 26 = I Year.
   - AcademicDataSeeder now creates USNs in the new format and stores the
     matching admission year (2023-2026).
   - AuthService accepts the new USN (case-insensitive) as a login name.
   - AI output guard enrolment-number regex updated.
   - One-time startup migration (UsnMigration) rewrote the 120 existing
     students from 1CG24CSnnn to 2BA<YY>CSnnn, keeping all attendance,
     marks, enrollments, assignments and submissions intact.
   - Database verified: 30 students in each of 2BA23CS001-030,
     2BA24CS001-030, 2BA25CS001-030 and 2BA26CS001-030.
   - credentials.txt regenerated with the new USNs (login email addresses
     are unchanged and still work).
   - Student passwords are unchanged: Student@123.

3. SEARCH BAR REMOVED
   - Removed the top-bar search input from the shared PortalTopbar, so it is
     gone from the admin, faculty and student portals.
   - Also removed the Ctrl+K shortcut that focused it.

4. GRID BOX REMOVED
   - Removed the unused apps/grid button that sat to the right of the date in
     the shared top bar (all portals).

5. SIDEBAR UNREAD BADGES
   - Notifications now carry a category: NOTICE, QUESTION_PAPER, MATERIAL,
     ASSIGNMENT, EXAM or INVIGILATION.
   - Notifications are created when:
       * an admin sends a broadcast (NOTICE)
       * faculty upload a question paper (QUESTION_PAPER)
       * faculty share study material (MATERIAL)
       * faculty create an assignment (ASSIGNMENT)
       * an exam is published (EXAM)
       * a faculty member is assigned invigilation duty (INVIGILATION)
       * a career-profile resume is approved/rejected (NOTICE)
   - Student sidebar shows counts on Notifications, Question Papers, Study
     Materials, Assignments and Examinations.
   - Faculty sidebar shows counts on Notices (inbox) and Invigilation Duties.
   - Opening a tab marks that category read and clears its badge immediately.
   - The top-bar bell still shows the total unread count.
   - The faculty Notices tab now also lists an Inbox of messages received from
     the admin (previously it only showed notices the faculty had sent).
   - Relative times ("Just now", "5m ago") are now parsed correctly: the
     backend serialises timestamps without an offset from a UTC container, so
     the shared helper treats offset-less values as UTC instead of browser
     local time. Fresh notifications no longer read "5h ago" in IST.

6. STUDENT - ASSIGNMENTS
   - Removed the "My submission" option from every assignment card.

7. STUDENT - EXAMINATIONS
   - Removed the "Hall ticket" button and all hall-ticket wording.

8. ADMIN - ATTENDANCE TAB REMOVED
   - Removed the Attendance nav item, tab renderer and the attendance tab
     component. Attendance analytics remain on the admin dashboard overview.

9. ADMIN - BROADCAST CENTER
   - New "Broadcast Center" item directly below "Placements".
   - Admin can send a direct notification to:
       * all students
       * students of one year
       * students of one department
       * all faculty
       * faculty of one department
       * one particular student
       * one particular faculty member
   - Each send is stored in a new broadcasts table with sender, audience,
     year/department/recipient, recipient count and timestamp; a per-user
     notification is created for every recipient.
   - The page lists all messages sent by the signed-in admin.

10. ADMIN - NOTICES & EVENTS
   - Now lists only broadcasts sent by the admin (previously it showed the
     latest notification rows belonging to any user).
   - Each entry shows the audience label and recipient count, e.g.
     "To All students - 120 recipients" or "To II Year students - 30
     recipients" or "To Student - Aarav Sharma".

11. FACULTY - CAREER PROFILE (REPLACES FACULTY DIRECTORY)
   - Faculty Directory removed from the faculty portal and replaced with
     Career Profile.
   - Faculty can upload, replace, download and remove their own resume
     (PDF/DOC/DOCX, max 10 MB). Uploads start as PENDING.
   - Faculty cannot see any other faculty member's resume; the directory
     endpoint is restricted to students and admins.
   - Status is shown as Not submitted / Pending review / Approved / Rejected,
     with the reviewer note when rejected.

12. ADMIN - RESUME APPROVAL
   - The Academics > Faculty table shows each resume status and Approve /
     Reject actions for pending uploads.
   - Admin uploads remain available and are auto-approved.
   - Students only see a resume in the Faculty Directory after approval, and
     the download endpoint enforces the same rule.

------------------------------------------------------------
NOT YET DONE / DEFERRED
------------------------------------------------------------

- AI services: deliberately not touched in this round.
- Admin sidebar badges: the admin is the sender of broadcasts and has no
  unread inbox, so no admin badge was added. Pending resume approvals are
  visible in Academics instead.

  category NOTICE on startup, so they count toward the Notifications badge.
